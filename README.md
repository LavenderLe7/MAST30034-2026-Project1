# Forecasting Borough-Level Late-Arrival Share for Completed WAV-Requested HVFHV Trips in New York City

> **MAST30034 Applied Data Science · Project 1: An End-to-End Data Science Project**

## Problem Description

Reliable wheelchair-accessible vehicle (WAV) service matters to passengers who
rely on it. Using 2025 New York City high-volume for-hire vehicle (HVFHV) trip
data, this project forecasts the share of completed WAV-requested trips in each
pickup borough whose vehicle arrives more than 10 minutes after the requested
pickup time, one four-hour period ahead. The forecast is an early signal for
human operational review, not automatic vehicle allocation.

## Dataset

The pipeline automatically downloads public 2025 data from:

- NYC TLC HVFHV trip records and Taxi Zone geography;
- NOAA Local Climatological Data; and
- archived HRRR weather forecasts.

## Approach

The notebook builds a borough-by-time modelling panel and compares a matured
24-hour history benchmark, a grouped-binomial GLM, and weighted XGBoost using a
chronological train, validation, and held-out evaluation design.

## Usage

> **Tested locally with:** Python 3.13.5 (Jupyter kernel: Python 3
> (ipykernel)) and OpenJDK 17.0.20. You also need Git, internet access, and
> about 10 GB of free disk space for the first run. No API key is required.

```bash
# Clone the repository
git clone https://github.com/MAST30034-AppliedDataScience/project-1-individual-LavenderLe7.git
cd project-1-individual-LavenderLe7

# Install dependencies
pip install -r requirements.txt

# Download the data
python3 download_data.py

# Open the analysis notebook
jupyter lab project_analysis.ipynb
```

Once JupyterLab opens, run all cells in `project_analysis.ipynb`. The first run
downloads the required data; later runs reuse local files.

## Recommendations

Forecasts should prioritise human review, not automate vehicle allocation.

- **Offer targeted driver incentives** only when live data confirm that WAV
  coverage cannot meet outstanding requests in a prioritised borough-period.
- **Prioritise recovery for outstanding WAV requests** when live status shows an
  active request is unassigned, loses an assigned vehicle, or is disrupted.
- **Run a platform-specific pilot before wider rollout** and scale, restrict,
  revise, or stop the workflow based on prospective service outcomes and cost.
